# Android app

The Android implementation uses Kotlin and Jetpack Compose. Speech recognition uses the device's on-device recognizer with automatic language detection where the OS provides it; the app does not publish a fixed source-language list. Translation targets are the 38 languages listed by Hy-MT2. Screen state, design tokens, and accessibility rules follow the [shared UX and design specification](../docs/shared-ux-spec.md).

`RealtimeTranslateApp.kt` renders the whole product on one screen: a title and status strip, a top language bar with one `OutlinedButton` + `DropdownMenu` chip per speaker (A left, B right; the menu carries a `Reading language` group and a `Spoken language` group split by a divider), an inline session banner (permission, model progress, model-load failure and retry, unloading, runtime error), a `LazyColumn` of chat bubbles with speaker A left-aligned and speaker B right-aligned, and a bottom row holding just the A and B push-to-talk controls, the hint line, and the session action. `RealtimeTranslateTheme.kt` holds the ZETIC minimal tokens plus the per-speaker identity families (`AccentA`/`DeepA`/`TintA`/`BorderA`, `AccentB`/`DeepB`/`TintB`/`BorderB`) and the `speakerAccent`/`speakerDeep`/`speakerTint`/`speakerBorder` lookups. The brand accent `#2DBDB2` is reserved for the session action and the model-load progress indicator; the speaker families cover the language chips, chat bubbles, and PTT controls. `ZeticWordmark` in `RealtimeTranslateApp.kt` renders the official ZETIC logo from `res/drawable-nodpi/zetic_logo.png`.

Pending parity with the [shared specification](../docs/shared-ux-spec.md), which iOS now follows: the session action still reads `Start conversation` / `End session` rather than the settled sentence-case `Start session` / `End session`, the banner still carries an `unloading` branch for a state nothing enters, and there is no cancel on the model download and no retry on a failed bubble.

`TurnTranslateRoot.kt` is everything that wraps around that screen: the settings drawer, the three first-run surfaces, and the session-comfort behaviors. The main screen is composed unchanged inside it, so opening the drawer or answering a first-run step never rebuilds it and never touches the Melange session. The drawer is a `ModalNavigationDrawer` with the layout direction flipped for the scaffold alone, which is what puts it on the trailing edge; the first-run surfaces are siblings of the drawer in one `Box`.

The decisions those surfaces make live outside the composables, so they are unit tested without a device. `FirstRun.kt` holds the remembered flags (`FirstRunPreferences`, `SharedPreferences`), the step selection, the metered-network reading, and the download-consent decision. `SessionComfort.kt` holds the keep-awake predicate, the four-event haptic table and its API-30 fallback, and the rule for what a long-pressed bubble copies. `SettingsDrawer.kt` holds `AppInfo`, the drawer copy, and the panel. `Toast.kt` is the one self-dismissing confirmation both the drawer and a copied bubble use. The Compose UI itself is the thin shell around all of it and is exercised by the instrumented tests, which need an emulator.

`SessionViewModel` gained one action, `ClearConversation`, guarded by the same `canClearConversation` rule the drawer row is disabled under. It is otherwise unchanged by the redesign. The idle main screen is `SessionPhase.Ready` with `conversationStarted = false`, and the live main screen is `SessionPhase.Ready` with `conversationStarted = true`; the UI switches the session action and the push-to-talk lock on that flag rather than navigating.
