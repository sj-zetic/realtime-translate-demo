# iOS app

The iOS implementation uses Swift and SwiftUI. Screen state, design tokens, and accessibility rules follow the [shared UX and design specification](../docs/shared-ux-spec.md).

`RealtimeTranslateRootView.swift` renders the whole product on one screen: a status strip, a top language bar with one `Menu` chip per speaker (A leading, B trailing; the menu holds two inline `Picker`s, `Reading language` and `Spoken language`), an inline session banner (permission, model progress, model-load failure and retry, closing, runtime error), a scrolling chat transcript with speaker A left-aligned and speaker B right-aligned, and a bottom safe-area inset holding just the A and B push-to-talk controls, the hint line with the typed-input keyboard glyph at its trailing end, and the session action. `DesignToken` holds the ZETIC minimal palette plus the per-speaker identity families (`accentA`/`deepA`/`tintA`/`borderA`, `accentB`/`deepB`/`tintB`/`borderB`), surfaced through a `Speaker` extension (`accentColor`, `deepColor`, `tintColor`, `borderColor`). The brand accent `#2DBDB2` is reserved for the `Start Session` action and the model-load progress indicator; the speaker families cover the language chips, chat bubbles, and PTT controls. `ZeticWordmarkButton` renders the official ZETIC logo in the navigation bar from the `ZeticLogo` image set in `Sources/Assets.xcassets`, followed by a small chevron, and opens the settings drawer.

`SettingsDrawerView.swift` is that drawer: a trailing-edge panel over a dim scrim, with the `Clear conversation`, `Visit zetic.ai`, and `Contact us` rows, the About block, and the bottom toast. `SettingsDrawerModel.swift` holds its state and its side effects, with the pasteboard, the URL opener, and the accessibility announcement injected so the copy, the clear, and the toast are testable without the UI. The clear itself is passed into `SettingsDrawerOverlay` as a closure plus an enabled flag, so the drawer still knows nothing about the view model behind it. `SettingsRow` takes an `isEnabled` flag; a disabled row stays in place in `color.textSecondary` rather than disappearing. New settings rows, including the deferred app-language row, slot into `SettingsDrawerPanel.rows`.

`TypedInput.swift` holds the [typed-input fallback](../docs/shared-ux-spec.md#typed-input): `TypedInputCopy` (every user-facing string, including the guidance line that names both ends of the turn), `TypedInputModel` (presentation, the remembered speaker, the draft, and the `hasDraft` gate), `TypedInputSheet` (the half-height sheet with its segmented speaker control, guidance, field, `Cancel`, and `Send`), and `TypedInputButton` (the keyboard glyph on the bottom bar's hint row). Sending calls `RealtimeTranslateViewModel.submitTypedTranscript`, which appends an already-finalized bubble and hands the trimmed text to `completeTurn`, the same private entry point a released push-to-talk control reaches through `receiveFinal`. There is one translation pipeline; typed input adds an entry to it, not a copy of it. `canSubmitTypedTranscript` is the push-to-talk gate (`state == .ready`) exposed to the view.

`LanguagePreferences.swift` remembers both speakers' language selections across launches. `LanguagePreferenceStoring` is the seam (`UserDefaultsLanguagePreferences` in the app, `EphemeralLanguagePreferences` everywhere else), `LanguagePreferenceDefaults` owns the four keys and the `-resetLanguages` launch argument, and `LanguageRestore.selection` is the single resolver both a fresh launch and a restoring one go through: the reading language restores verbatim, the spoken language derives from it, and a stored spoken identifier is applied on top only when it differs from that derived value and still names a recognizer this device has. The store is injected only in `RealtimeTranslateViewModel.fromLaunchArguments`, so a view model built anywhere else remembers nothing and no test reads what the host app last wrote. `RealtimeTranslateViewModel.clearConversation` empties the transcript without touching the session, gated by `canClearConversation`.

`SessionComfort.swift` holds the three [session-comfort behaviors](../docs/shared-ux-spec.md#session-comfort) and, more to the point, their decisions: `ScreenAwakePolicy` and `ScreenAwakeController` (which states hold `UIApplication.isIdleTimerDisabled`, applied from the root view's scene phase), `HapticEvent` and its mapping to a `HapticFeedback` sensation (played through a `HapticSink` the view model is given, `SystemHaptics` in the app and a spy in tests), and the copy path: `ConversationItem.copyableText`, `ConversationCopyModel`, and the shared `ToastCenter`. The UIKit effects are untestable, so each decision is a pure function or a small state machine over an injected sink and is unit tested on its own. The `Toast` view and `ToastLayer` live in `RealtimeTranslateRootView.swift` next to `ThinDivider`, and both the drawer's copy row and a copied chat bubble render them.

`SpeechOutput.swift` holds [spoken translation](../docs/shared-ux-spec.md#spoken-translation) and its decisions: `SpokenTranslation.decision` (whether a bubble speaks and in which language, the one rule both the automatic announcement and the replay button go through), `ConversationItem.speakableTranslation` (which is also what decides whether a bubble shows a replay glyph), `SpeechVoice.match` (the exact, implied-variant, language-only, silent fallback chain from a Hy-MT2 reading code such as `zh-Hant` to an installed voice such as `zh-TW`), `SessionState.isRecognizerLive`, and the record/playback handoff. `SpeechAudioCoordinator` owns that handoff over an injected `SpeechAudioSession`, claiming `.playback` once and releasing it once, which is what keeps a replaced sentence from becoming an audible route change and keeps a late synthesizer callback from deactivating a session the recognizer has since claimed. `SystemSpeechOutput` is the thin `AVSpeechSynthesizer` shell around all of it, and the view model is given a `SpeechOutput` (a fake in tests). The view model stops speech synchronously in `beginTurn` and `beginNewSession`, so nothing is ever spoken over an open microphone. The mute preference lives under the single `@AppStorage` key `SpeechOutputDefaults.mutedKey`, written by the status strip's toggle and read by the view model when it seeds itself.

`RealtimeTranslateViewModel` keeps the same states and the same model and speech lifecycle. The redesign added three read-only view flags: `canEditLanguages` (false while an utterance is in flight or the model is loading or unloading), `isSessionLive` (the model is loaded, so the A/B controls and `End Session` belong on screen), and `canStartSession`.

For a device build, provide `MELANGE_PERSONAL_KEY` as an Xcode build environment variable. The value is expanded into the built app's `Info.plist` so the installed demo can load its model; it is not tracked in this repository. Treat that demo artifact as credential-bearing and do not distribute it.
