# iOS app

The iOS implementation uses Swift and SwiftUI. Screen state, design tokens, and accessibility rules follow the [shared UX and design specification](../docs/shared-ux-spec.md).

`RealtimeTranslateRootView.swift` renders the whole product on one screen: a status strip in a top safe-area inset, a top language bar with one `Menu` chip per speaker (A leading, B trailing; the menu holds two inline `Picker`s, `Reading language` ordered by `TargetLanguage.menuOrder` and `Spoken language`), an inline session banner (permission, model progress with its cancel, model-load failure and retry, runtime error), a scrolling chat transcript with speaker A left-aligned and speaker B right-aligned, and a bottom safe-area inset holding just the A and B push-to-talk controls, the hint line with the typed-input keyboard glyph at its trailing end, and the session action. `DesignToken` holds the ZETIC minimal palette plus the per-speaker identity families (`accentA`/`deepA`/`tintA`/`borderA`, `accentB`/`deepB`/`tintB`/`borderB`), surfaced through a `Speaker` extension (`accentColor`, `deepColor`, `tintColor`, `borderColor`). The brand accent `#2DBDB2` is reserved for the `Start session` action and the model-load progress indicator; the speaker families cover the language chips, chat bubbles, and PTT controls. The navigation bar holds three things: `ZeticWordmark` on the leading edge, which renders the official ZETIC logo from the `ZeticLogo` image set in `Sources/Assets.xcassets` as decoration announced `ZETIC` and nothing more, the centered `AppText.productName` title, and `SettingsMenuButton` on the trailing edge, which is the `SettingsMenuGlyph.menu` three-line glyph alone in a full `Layout.tapTarget` box, announced `Settings`, and opens the settings drawer. All three items opt out of the iOS 26 glass capsule through `sharedBackgroundVisibility(.hidden)`, and all three fit at every Dynamic Type category up to `accessibility5`, so none of them hides or truncates.

`Layout` holds the three numbers that keep the main screen bounded at every text size: `tapTarget` (44, the minimum edge of every icon-only control), `hintCeiling` (`.accessibility1`, above which the bottom bar drops its hint line and the session banner starts scrolling inside a bounded box), and `bannerCeiling` (how tall that box may grow before the transcript pays for it). The banner is bounded only when `RealtimeTranslateViewModel.hasSessionBanner` says there is one, so no other state inherits an empty box, and it takes layout priority over the transcript's own greedy scroller. `SessionState.title` and `ConversationEmptyHint.text(for:)` are the two per-state strings, both pure functions of the state and both unit tested against every case.

`SettingsDrawerView.swift` is that drawer: a trailing-edge panel over a dim scrim, with the `Clear conversation`, `App language`, `Visit zetic.ai`, and `Contact us` rows, the About block, and the bottom toast. `SettingsDrawerModel.swift` holds its state and its side effects, with the pasteboard, the URL opener, and the accessibility announcement injected so the copy, the clear, and the toast are testable without the UI. The clear itself is passed into `SettingsDrawerOverlay` as a closure plus an enabled flag, so the drawer still knows nothing about the view model behind it. `SettingsRow` takes an `isEnabled` flag; a disabled row stays in place in `color.textSecondary` rather than disappearing, and `SettingsRowLabel` is the shared layout so the language row's `Menu` and the three action rows are laid out by one piece of code. There is no `Storage` row and no destructive action left in the drawer, so it holds no alert of its own. New settings rows slot into `SettingsDrawerPanel.rows`.

`TypedInput.swift` holds the [typed-input fallback](../docs/shared-ux-spec.md#typed-input): `TypedInputCopy` (every user-facing string, including the guidance line that names both ends of the turn), `TypedInputModel` (presentation, the remembered speaker, the draft, and the `hasDraft` gate), `TypedInputSheet` (the half-height sheet with its segmented speaker control, guidance, field, `Cancel`, and `Send`), and `TypedInputButton` (the keyboard glyph on the bottom bar's hint row). Sending calls `RealtimeTranslateViewModel.submitTypedTranscript`, which appends an already-finalized bubble and hands the trimmed text to `completeTurn`, the same private entry point a released push-to-talk control reaches through `receiveFinal`. There is one translation pipeline; typed input adds an entry to it, not a copy of it. `canSubmitTypedTranscript` is the push-to-talk gate (`state == .ready`) exposed to the view.

`LanguagePreferences.swift` remembers both speakers' language selections across launches. `LanguagePreferenceStoring` is the seam (`UserDefaultsLanguagePreferences` in the app, `EphemeralLanguagePreferences` everywhere else), `LanguagePreferenceDefaults` owns the four keys and the `-resetLanguages` launch argument, and `LanguageRestore.selection` is the single resolver both a fresh launch and a restoring one go through: the reading language restores verbatim, the spoken language derives from it, and a stored spoken identifier is applied on top only when it differs from that derived value and still names a recognizer this device has. The store is injected only in `RealtimeTranslateViewModel.fromLaunchArguments`, so a view model built anywhere else remembers nothing and no test reads what the host app last wrote. `RealtimeTranslateViewModel.clearConversation` empties the transcript without touching the session, gated by `canClearConversation`.

`AudioInterruption.swift` holds [audio interruption recovery](../docs/shared-ux-spec.md#audio-interruptions) and its decision: `AudioInterruptionEvent` (began, ended with the system's `shouldResume` hint, route lost) with the two pure translators that read `AVAudioSession`'s notification payloads, `AudioInterruptionPolicy.response` (the whole table: abandon the utterance while the recognizer holds the microphone, stop speech while a translation is being read, ignore everything else, and never act on an interruption ending), `AudioInterruptionCopy`, and the `AudioInterruptionObserving` seam (`SystemAudioInterruptions` over `NotificationCenter` in the app, a stub in tests). The view model is given one and applies the response in `handleAudioInterruption`; `abandonUtterance` is `beginTurn`'s failure path reused, plus the one-line `notice` the session banner renders. The model and the session are untouched, and the recognizer reactivates its own audio session on the next start, so nothing has to be rebuilt for the next push-to-talk.

`LocalModelStore` carries the read-only `footprint(forModelName:cacheRoot:)` and the scoped `deleteModel(forModelName:cacheRoot:)`, which follows the same tolerant, contained rules `sweepOrphans` follows: an index that will not parse is refused, a model key that is not a plain directory name inside `artifacts/` is refused before any path is built from it, the rewritten index has to serialize before anything is removed, and `backend-selection-*` and `staging-locks` are never touched. Both are [dormant](../docs/shared-ux-spec.md#model-storage): the drawer's `Storage` row and its whole `ModelStorage.swift` layer are gone, and nothing in the app calls them. They stay whole and stay under test because the containment rules are the hard part, and a later row or a low-storage prompt should find them rather than write them again. The one byte-count formatter moved to `ModelDownloadSize.size(bytes:)`, beside the download size it formats.

`Localization.swift` holds the [localization](../docs/shared-ux-spec.md#localization) plumbing: `AppText.productName` (the one string that is never translated), `AppLanguage` and `AppLanguageDefaults` (the in-app override, its `app.language` storage key, the `AppleLanguages` write iOS reads at launch, and the `-resetAppLanguage` launch argument), `AppLanguageCopy`, `SessionActionCopy` (the bottom bar's one slot, named once: `Start session`, `End session`, `Cancel`), `PermissionCopy`, and `TranslationFailureCopy`. That last one exists because `MelangeTranslationRuntime` is left alone: its `TranslationRuntimeError` descriptions are localized at the display site instead, where `RealtimeTranslateViewModel` puts a failure on screen, and anything it does not recognize keeps the system's own `localizedDescription`. Every user-facing string lives in `Sources/Localizable.xcstrings`, with `en` as the development language and `fr` and `es` complete: every key translated in both, in the registers the [spec](../docs/shared-ux-spec.md#localization) fixes (vouvoiement in French, tú in Spanish), with the French typography carried as real code points and asserted by tests. The 38 reading-language names are deliberately not in the catalog: `TargetLanguage.displayName` and `.menuName` get them from `Locale`, while `.name` stays English and reaches only the Hy-MT2 prompt. `LOCALIZATION_PREFERS_STRING_CATALOGS` and `SWIFT_EMIT_LOC_STRINGS` make a build emit `.stringsdata`; `xcrun xcstringstool sync Sources/Localizable.xcstrings --stringsdata <each file under the target's build directory>` merges them into the catalog. Source-language entries have to be marked `translated` in the catalog to be compiled: `xcstringstool compile` skips anything still in the `new` state, and a catalog that compiles to nothing means every explicit key renders as its own key. The settings drawer's `AppLanguageRow` is the one control, and `RealtimeTranslateRootView` applies `\.environment(\.locale,)` at the root so literals in views follow an override immediately while model-built strings follow the bundle on the next launch.

`SessionComfort.swift` holds the three [session-comfort behaviors](../docs/shared-ux-spec.md#session-comfort) and, more to the point, their decisions: `ScreenAwakePolicy` and `ScreenAwakeController` (which states hold `UIApplication.isIdleTimerDisabled`, applied from the root view's scene phase), `HapticEvent` and its mapping to a `HapticFeedback` sensation (played through a `HapticSink` the view model is given, `SystemHaptics` in the app and a spy in tests), and the copy path: `ConversationItem.copyableText`, `ConversationCopyModel`, and the shared `ToastCenter`. The UIKit effects are untestable, so each decision is a pure function or a small state machine over an injected sink and is unit tested on its own. The `Toast` view and `ToastLayer` live in `RealtimeTranslateRootView.swift` next to `ThinDivider`, and both the drawer's copy row and a copied chat bubble render them.

`SpeechOutput.swift` holds [spoken translation](../docs/shared-ux-spec.md#spoken-translation) and its decisions: `SpokenTranslation.decision` (whether a bubble speaks and in which language), `ConversationItem.speakableTranslation` (which is also what decides whether a bubble shows a play glyph), `SpeechVoice.match` (the exact, implied-variant, language-only, silent fallback chain from a Hy-MT2 reading code such as `zh-Hant` to an installed voice such as `zh-TW`), `SessionState.isRecognizerLive`, and the record/playback handoff. `SpeechAudioCoordinator` owns that handoff over an injected `SpeechAudioSession`, claiming `.playback` once and releasing it once, which is what keeps a replaced sentence from becoming an audible route change and keeps a late synthesizer callback from deactivating a session the recognizer has since claimed. `SystemSpeechOutput` is the thin `AVSpeechSynthesizer` shell around all of it, and the view model is given a `SpeechOutput` (a fake in tests). The view model stops speech synchronously in `beginTurn`, `clearConversation`, and `beginNewSession`, so nothing is ever spoken over an open microphone. Speech is [tap only](../docs/shared-ux-spec.md#spoken-translation): `replay(_:)` from a bubble's play control is the single caller of `speak`, a delivered translation is not announced, and the mute toggle, its `speech.muted` preference, and its two glyphs are gone.

The app is locked to the light appearance (`UIUserInterfaceStyle = Light` in `Sources/Info.plist`) rather than growing a dark `DesignToken` variant; the reasoning is in the spec's [appearance](../docs/shared-ux-spec.md#appearance) section. Dynamic Type is handled by wrapping text and scrolling containers rather than truncating: the drawer panel scrolls, the first-run surfaces use `ViewThatFits` to stay centered while they fit and scroll when they do not, and the language chips are the one place a shrink is allowed.

`RealtimeTranslateViewModel` keeps the same model and speech lifecycle, and exposes read-only view flags rather than letting the view read the state machine: `canEditLanguages` (false while an utterance is in flight or the model is loading), `isSessionLive` (the model is loaded, so the A/B controls and `End session` belong on screen), `canStartSession`, `canCancelModelPreparation`, `canRetryTranslation`, `canReplay`, and `hasSessionBanner`. `SessionState` no longer carries `endingSession` or `ended`: nothing assigned the first and only a launch argument reached the second. `.error` carries a `SessionFailure` rather than a bare string, so the banner offers the system prompts for a refused permission and a plain `Try again` back to `.ready` for anything else, instead of re-requesting a microphone the app already holds and dropping the loaded session for nothing. `retryTranslation(_:)` and `completeTurn` share one `startTranslation`, so a retry is the same round trip the first attempt made. `concludeUtterance` is the single exit from `finalizing`, taken by a final that arrives after the release, one that arrived before it (remembered even when empty, so a release never waits on a callback that already came), or `finalizingTimeout`, a six second watchdog bound to that utterance whose delay is injected so a test fires it rather than waits it out.

The app is iPhone only: `TARGETED_DEVICE_FAMILY` is `1` in both `project.yml` and the generated `RealtimeTranslate.xcodeproj`, because there is no iPad layout and the copy says `on this phone` throughout.

The deployment target is iOS 16.6 because the ZeticMLange 1.10.0 binary is built for iOS 16.6 or later.

For a device build, provide `MELANGE_PERSONAL_KEY` as an Xcode build environment variable. The value is expanded into the built app's `Info.plist` so the installed app can load its model; it is not tracked in this repository. Treat any such artifact as credential-bearing and do not publish it. Client distribution should use a client-scoped, revocable credential rather than a developer's personal key.

An iOS IPA is not universally sideloadable like an Android APK. A `debugging` or `release-testing` export installs only on devices covered by its provisioning profile. For external client testing, TestFlight is the preferred path and requires an App Store Connect account, an Apple Distribution certificate, and a matching distribution profile for `ai.zetic.realtimetranslate`.
